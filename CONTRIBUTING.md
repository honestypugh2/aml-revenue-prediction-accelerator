# Contributing

Thank you for your interest in improving the revenue prediction accelerator.

## Ground rules

1. **Customer neutrality is mandatory.** Never add customer names, acronyms,
   participant names, organization-specific facility names or identifiers, real
   patient information, realistic patient names, medical record numbers, actual
   finance data, contact details, or any cloud identifiers/secrets. Use neutral
   placeholders (`FAC-001`, `WORKSPACE_PLACEHOLDER`, `LAKEHOUSE_PLACEHOLDER`).
2. **Synthetic data only.** All sample data must be generated by the synthetic
   generator or clearly-licensed, redistributable sources documented in
   [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).
3. **Leakage safety.** Features must never use information from after a
   snapshot's `snapshot_date`. Preserve time-aware splitting and the leakage
   tests.
4. **No SDK v1.** Use the Azure Machine Learning Python SDK v2 exclusively.

## Development setup

```bash
uv sync --all-extras
uv run pre-commit install
```

## Quality gates (run before every PR)

```bash
make check   # ruff lint + pyright + pytest
make format  # ruff format
```

All of the following must pass:

- `uv run ruff check src tests`
- `uv run ruff format --check src tests`
- `uv run pyright src`
- `uv run pytest`

New behavior requires tests. Cloud-touching code must keep imports guarded and
add opt-in `live`-marked tests rather than requiring credentials in CI.

## Commit and PR conventions

- Keep changes focused and well-described.
- Update relevant docs and, when reusing third-party material, update
  `THIRD_PARTY_NOTICES.md` and the relevant ADR.
- Do not commit `.env`, generated data, model artifacts, or Terraform state.
